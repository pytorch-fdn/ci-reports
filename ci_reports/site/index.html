PyTorch Foundation CI Reports

Combined total (all owning accounts: LF, Meta, AMD) per month. Hover a month to highlight it; on Financials and Runtime, click anywhere in its column to open that month's detailed report. View vendor/architecture mappings & coverage gaps →

Data trust: Data from the PyTorch Foundation AWS account (LF) is billing-grade and trusted. Figures from PyTorch HUD (Meta) and AMD-provided pricing are estimates, not confirmed real costs -- there is no ground truth for either. This report does not include self-hosted runner costs provided directly by member companies.

Reproduction fidelity: LF is reproduced exactly from the AWS billing export. Meta and AMD are recomputed for the full calendar month using a consistent query methodology, so a previously published figure for the same month may differ slightly from an earlier one-off export. See each month's detailed report for the full explanation.

All metrics, month by month

Runtime is in hours, not dollars (AMD cost is not recorded upstream and the billing export has no workflow dimension), so these figures describe CI job records and will not equal the Runtime tab's billed instance-hours. Counts and hours cover only repos present in the PR, job and runtime data for that month. Months before runtime data begins show no hours, not zero. Contributors are distinct PR authors, bots excluded.

This breakdown covers instance-hours only -- usage billed in other units (data transfer, storage, requests, etc.) isn't attributable to an architecture and is excluded here, so the bars sum to less than that month's total usage across every charge type.

Months are snapshotted once and then treated as immutable, so this trend is stable across rebuilds. A runner type or instance family not yet in the mapping tables never excludes a month -- its cost, when known, is shown under an explicit "N/A" architecture in that month's detailed report instead of being hidden.
